# ADR 0058: Browser Routing

Status: accepted.
Date: 2026-10-25

## Context

Route recognition, path construction, native history writes and change events
were maintained separately from application view dispatch and workspace state.
Adding route families required keeping these implementations synchronized. The
existing URL transport and Search/reading lifetimes are product contracts that a
routing library must preserve.

## Decision

TanStack Router owns one generated file-based route tree, typed destinations,
matching, global location subscriptions and browser history. The Vite plugin and
explicit generation command support both development and clean-checkout checks.
Route files delegate to existing feature owners. The handwritten route union,
regex dispatcher and custom change event are removed.

The persistent application layout owns theme, readiness, profile selection and
Search. React Activity keeps Search mounted and hides it across other routes;
Search requests remain disabled outside Search. TanStack Query continues to own
requests, immutable reference caches and generation retirement. Router loaders
and preloading do not introduce a parallel data cache or semantic inference.

Transport codecs retain string values and repeated sort priority. The record key
in the pathname is the sole reading identity. Optional casting rank uses `rank`;
exact selection and independent parent landing use the bounded, versioned compact
`at` and `focus` address codecs. Those addresses omit the repeated record key and
empty trailing values while retaining embedded owner identities, source
fingerprints and passage hashes. The browser checks transport shape and bounds;
backend policy remains authoritative for source availability and meaning. The
retired JSON `selection`/`landing` parameters are rejected without a legacy
decoder. Native section fragments remain separate from exact addresses. Filter
recovery replaces only failed transport and preserves independent criteria and
reading. Page and embedded-owner return context live in Router history state.
Typed destination factories centralize native hrefs; embedded-owner return policy
remains explicit application policy. Modified links retain native behavior.

Router restores page scrolling. Existing bounded list/reader positions and Drawer
history/focus remain with shared reading owners. URL updates restore only changed
criteria/reading addresses, preserving unfinished local editors and in-progress
reading when paging or changing profiles.

## Consequences

New pages are added through route modules and generated type linkage rather than
another pathname parser. Product URL codecs and exact reading policies remain
Atlas-owned. Generated tree output is tracked and regenerated by tests,
typechecking and builds. Routing adds a frontend dependency and build-generation
step; it does not promise a smaller bundle, faster retrieval, SSR, new navigation
prompts or changed product semantics.
