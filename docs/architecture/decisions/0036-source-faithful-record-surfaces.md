# ADR 0036: Source-Faithful Record Surfaces

Status: accepted at Checkpoint B; creature, hazard, and spell surfaces completed through direct cutover
Date: 2026-08-24

## Context

Atlas needs coherent record selection, preparation, agent, and encounter views without duplicating canonical semantics across CLI, app DTOs, and frontend code. It also needs to preserve authored content and runtime adjustments without keeping the current creature fallback as a permanent second record.

## Decision

`atlas-app-service` composes three app profiles through generated `atlas-app-model` DTOs:

- `search_compact` for identity, teaser, scan facts, compact traits, and source;
- `record_detail` for complete scan-first awareness, skills, defenses, movement, strikes, spellcasting, abilities, resources/gear, owned content, graph-backed record references, and provenance; and
- `encounter_participant` for participant state, final values and explanations, conditions, turn/action state, usable activities, resources, and source-backed capabilities.

All three use one `RecordSurfaceView` outer contract with common record/source metadata, a profile tag, a tagged entity-specific presentation body, optional common user issues, optional record-detail references, and an optional exact encounter bag. `EncounterParticipantView.record_view` carries the participant's projected `RecordSurfaceView`. `atlas-record` applies one typed `Render | Omit | Provenance | Issue` expectedness policy to already-classified creature, hazard, and spell facts; app-service localizes and deduplicates actionable issues without parsing paths or prose. Optional absence and known-empty values are silent, false and zero remain known, supported source-only metadata remains provenance, and required unsafe or populated unmodeled facts remain actionable. Creature and hazard bodies represent every zero-or-one semantic domain as an optional named typed object; arrays are reserved for true-many activities and owned content. Internal entity/occurrence relationships remain canonical provenance and do not appear as human record links. Standalone spells use owned content, a compact backend-ordered human form catalog, and one mandatory effective form produced from the requested form/rank resolver result; base `Unsupported` remains actionable and whole-form or field-local `Unavailable` results stay localized. Spell and ritual outer metadata omits generic level and traits: the effective form's classification is their sole app owner, and the typed body family owns the `Spell` or `Ritual` label. The app body does not duplicate a display base definition or expose authored patch trees. Record detail projects the existing graph result once at the outer surface with deterministic order, totals, truncation, and typed nonfatal errors. Its default is outgoing 8/backlinks not requested, while explicit backlink limits use the same common owner. Search-compact and encounter profiles perform no implicit graph read. Stable profile order and density are app-service policy, so there is no generic section or string-key semantic lookup. Families without a creature, hazard, or spell owner return the explicit unavailable presentation boundary.

Encounter runtime composition is a prerequisite contract, not a generic profile implementation. `EncounterRuntimeView` uses named typed fields for zero-or-one semantic areas and typed collections for genuinely repeated domains. It owns current/temporary HP, conditions, action state, final adjusted values, applied/suppressed explanations, and tagged provenance. Runtime activities carry their canonical occurrence traits and associated typed rich content directly. The encounter creature body retains only canonical facts without runtime counterparts: IWR and hardness, AC context without static AC, authored save notes/details without static modifiers, and senses/languages/details without static perception. This gives consumers one composed response without static/runtime duplication, a second fetch, or a client join. Static and runtime spell rows directly own authored embedded spell content resolved through typed occurrence or exact actor-local target associations; claimed documents are removed from general content, repeated occurrences remain independent, and association ambiguity fails affected rows closed. Runtime spellcasting nests canonical entry labels/order/preparation/tradition with final attack/DC/slots and ordered occurrence spells; creature-parent spells remain explicit with content under static and runtime `standalone_spells`, unrelated embedded capability content remains general, and spell rows are absent from generic activities. Each runtime spell row also exposes typed cast availability and its exact spend ownership: prepared slot, spontaneous rank pool, innate occurrence use, focus pool, or stateless at-will. App-service initializes only supported typed canonical current values into durable participant-local state, validates the requested occurrence and spend owner on each cast or restore, and exposes typed unavailable state instead of guessing when current facts or ownership are absent or ambiguous. Encounter resource rows remain present when a typed runtime consumer exists even if current state is unavailable, or when supported participant-local current state exists without a consumer; an unattached provenance-only resource remains available on the static record but is omitted from encounter runtime. A separate typed destructive confirmation invokes the atomic generic participant reset; availability is false for legacy rows without a creation baseline, while successful results enumerate reset and preserved domains. Automatic daily-rest and refocus behavior remains out of scope. `StatBlockView`, `StatValueView`, generic section/value arrays, target-string semantic lookup, and consumer-side owner joins are not compatibility surfaces.

Top-level hazards now use the same exact encounter bag through their canonical `RecordBody::Hazard`. App-service projects authored defenses, number-only saves, ordered action/strike occurrences, and occurrence-owned content directly; missing or unsupported members stay unavailable per activity. Hazard strike activities expose optional typed melee/ranged mode plus the approved derived one-action cost only through the canonical attack-mode and strike-cost projections; the family/capability guard prevents non-Strikes from inheriting them, malformed traits do not default to melee, and authored non-Strike action costs remain authoritative. Guarded detection DC, broken threshold, and complex-hazard Stealth initiative suggestions call the central non-persisted hazard convenience owner. Initiative remains unset until user input. Local-state schema 8 stores Active/Disabled independently from the generated artifact and captures it in the participant creation baseline; Disabled removes only that hazard from turn rotation, remains visible, does not blanket-disable its activities, and never advances the turn as a side effect. No raw JSON, metric-key, label, or prose fallback supplies hazard behavior. Hazard-owned ActiveEffect, Adventure, and Token registry contexts remain excluded from runtime.

The runtime DTO exposes only user-relevant incomplete automation as stable typed limitation codes with typed participant, condition, activity, or spellcasting placement targets. Limitation messages are display-only. Projection diagnostics for malformed, duplicate, unsupported, unmapped, raw-path, publication, null, and source-noise facts stay internal to app-service, and missing or unsafe critical data fails closed or leaves the affected typed value unavailable. Raw source and provenance remain separately owned rather than being copied into a generic public note bag.

`atlas-web` remains transport. `web/atlas-ui` uses Ant Design for generic application controls and PF2e-specific components for record/runtime layouts. It renders generated semantics and hosts feature-owned interaction slots; it does not parse Foundry JSON or prose, infer mechanics, or reconcile static and runtime facts. Encounter-profile creature bodies omit canonical mechanics represented by the attached runtime bag, preventing duplicate canonical and final adjusted values in one response while retaining owned content and provenance.

ADR 0023 remains authoritative for CLI JSON. CLI record-bearing commands share one `atlas-record::RecordJson`: a genuinely common flattened base plus a mandatory tagged entity presentation. Creature, hazard, and spell bodies directly expose their family-owned typed semantics. Detail levels omit unhydrated entity members rather than emitting empty placeholders; empty members remain only for included sections where known-empty is intentional. Rich content remains supplementary. Families without one of those canonical bodies use an explicit registry-bound `unmigrated` boundary only until their family plan lands. The earlier additive generic-section direction is superseded; this unreleased contract is replaced directly with no compatibility shim, dual serializer, or feature switch. App DTOs and a parallel CLI semantic model remain forbidden.

The ordinary terminal renderer keeps ownership identities, occurrence locators, authored map keys, and opaque spell-form IDs as placement rules rather than headings. Creature content appears under natural record, ability, spell, equipment, Lore, or note labels, and spellcasting uses entry-to-rank hierarchy with distinct ordered rows. Hazard output composes defenses from typed facts, including one HP/temporary-HP/broken-threshold placement, and labels Strike mode and cost only from their named typed projections. Spell output presents rank and traits once, uses semantic damage and heightening labels while associating rows through retained typed keys, suppresses optional or known-empty sections, and derives unnamed form labels only from an already-resolved typed form result. Both families consume the shared expectedness and issue owners; the terminal does not parse raw paths, labels, or prose to recover semantics. `atlas record provenance <canonical-key>` is the separate typed diagnostic surface for full fact provenance, occurrence identities and locators, content ownership, verified edition context, embedded relationships, and exact reference/backlink provenance. Hazard occurrence-to-entity links are labeled as component membership there rather than record relationships. Its optional `--json` uses the shared envelope; it does not parse or expose raw source and does not change Full or `--include-raw` semantics.

The CLI and app projections receive the `atlas-record`-owned `RetrievedRecord` aggregate produced by index canonical hydration and preserved by search. Both read creature presentation values exclusively from `RecordBody::Creature`; hydrated creature records carry no generic record mechanics. App-service consumes the complete aggregate for its typed record-surface profiles and passes the complete aggregate to the local CLI.

`RichDocument` remains the once-parsed authored content tree. Record, entity, occurrence, child, content, and section targets remain addressable. The default child embedding policy remains overflow-only. Copied embedded capability prose stays reachable through its owner but is excluded from default ranking to prevent duplicate-result flooding, not because of authorization.

For creature activity presentation, app-service resolves an activity's typed occurrence target and composes its occurrence-owned content with content owned by the exact targeted actor-local entity. The activity exposes those documents once as ordered typed rich-content blocks and general overview/lore excludes them. Association failure is fail-closed for that activity. `atlas-record` owns the structured `RichDocument` projection, including authored paragraph/divider boundaries and a typed Foundry `Check` inline carrying display fallback plus optional statistic and numeric DC; web rendering consumes that DTO without label matching, ID parsing, raw HTML parsing, or a frontend join.

Current CLI/app/UI behavior inherits pinned-source default-visible/public-only routing and is not GM-complete. The implemented contract preserves typed visibility, role, and provenance as metadata while preventing classification-only suppression of useful authored information; no present security boundary is claimed. Creature, hazard, and standalone-spell presentation now use only their canonical bodies; the independent final production and visual gate remains separate and is not authorized by this cutover.

A4 screenshots remain diagnostic only. F3 automation follows F2 and covers the complete hashed fixture/viewport/theme/static/runtime matrix, including rejection of classification-only suppression. The recorded Checkpoint E gate precedes G1 fallback removal, and G2 separately verifies the complete evidence chain.

## Consequences

Search, CLI, app, and UI can differ in projection shape while deriving from one canonical semantic record. Runtime final values replace duplicate base display values. The hazard app/API contract is a tagged static body projected from `RecordBody::Hazard` plus the separately typed encounter runtime bag; checked-in TypeScript preserves both contracts, including the explicit typed provenance projection for approved source-only hazard metadata. Standalone spell and ritual UI renders the compact backend-ordered form catalog and the one exact effective-form response; it never receives authored patch trees or a duplicate display base. Its opaque form/rank request uses the existing record-detail endpoint, and request identity prevents an older response from replacing a newer choice. Neither Ant-based surface reconstructs mechanics from raw fields, labels, metrics, or prose; spell range display remains authored text, while image paths are not fetched or rendered and license metadata is not ordinary content. Generic `AtlasRecord.mechanics`, item hydration, and metric hydration are absent for canonical spell records; spell query rows remain one-way filter and discovery projections. Families other than creature, hazard, and spell keep exact H1-H11 ownership and require separate plans and approvals.
