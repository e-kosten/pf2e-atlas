# v0.1.0

PF2e Atlas 0.1.0 is the first stable release. Find Pathfinder Second Edition
rules and creatures by describing what you need, save what you find, and run
encounters from the same local workspace.

## From prep to play

- **Find a creature by idea or a rule by name.** Try “a guardian for an enchanted
  forest,” then narrow the results by level, rarity, or trait. Open a creature
  to read its abilities, follow a linked rule, or choose **Similar** to find
  alternatives. Where legacy and remaster entries are paired, you can move
  between them.
- **Keep your session notes with the rules.** Save creatures, spells, equipment,
  and other finds to a list. Add a Markdown note to an entry, and link to another
  record by typing `[[` and its name so you can open it during play.
- **Build an encounter for your party.** Enter PCs by name or import a
  Pathbuilder JSON export and review the suggested rule links for their abilities.
  Add the party, choose creatures or hazards, and preview how each addition
  changes the difficulty and suggested XP per PC.
- **Pick up at the saved turn.** Set initiative, track HP, conditions and spell
  resources, and add a countdown for an ability such as a breath weapon. Reopen
  the encounter next session with its round and current participant intact.

For a walkthrough, see [Getting started](https://github.com/e-kosten/pf2e-atlas/blob/release/v0.1.0/docs/getting-started.md).

## Install and open Atlas

On an Apple Silicon Mac running macOS Tahoe 26 or later, or on a Windows x64 PC,
install **PF2e Atlas Desktop** and choose **Set up Atlas**. Setup downloads the
Foundry PF2e 8.7.0 reference content and prepares it for local search.

For Linux, or if you prefer a browser, install the full CLI and run `atlas setup`.
Then run `atlas web --open` to open the same interface in your browser. You can
also work directly in the terminal. Try `atlas search "low level healing spell" --kind spell`,
or run `atlas agent skills install` to give your AI agent instructions for using Atlas.

## Upgrading from a prerelease

- **Existing workspaces.** Close other Atlas sessions using the workspace before
  updating it. Atlas keeps a saved-state backup before changing the database
  schema. Older workspaces may need an intermediate upgrade to preserve saved
  work. [Workspace upgrade instructions](https://github.com/e-kosten/pf2e-atlas/blob/release/v0.1.0/docs/setup-and-maintenance.md#upgrade-an-older-prerelease-workspace)
- **Sharing encounters.** Every new standalone encounter file uses **v4**.
  Recipients need a build that reads v4. Atlas still imports v1–v3 files. When
  you import an encounter, Atlas can flag a changed record linked only from GM
  or participant notes if the export includes its fingerprint.
- **Blank titles.** New lists and encounters need a name. Give an older
  blank-titled standalone file a name before importing it. Full-workspace
  recovery preserves the original title.
- **Windows installs.** Choose a dedicated folder for Atlas Desktop. If the
  installer finds runtime DLLs whose ownership it cannot verify, choose a
  separate folder.
- **Edits during play.** If a preview fails while you edit a condition’s
  magnitude inline, Atlas restores the saved value. You can also edit a note
  on an older condition whose magnitude is unknown.
  On Windows, Atlas asks before closing a disconnected workspace window that
  may have unsaved edits.

<summary>CLI and HTTP API compatibility for prerelease integrations</summary>

If you script Atlas, pin the version you use and check the commands or routes
your integration calls. During 0.x, defaults and response shapes can change.

**Search and record reads**

- Search returns records by default in text and JSON. Use `--detail preview` for
  the former `standard` best match or `--detail full` for all matches. Use a
  record key or a match’s `navigation` with `record get` in place of `open_args`.
  Similar still accepts `--explain`.
- `filters fields --json` returns group summaries. Use `--detail full` for the
  grouped descriptors or `--all --json` for the flat catalog. Count-free filter
  vocabulary pages return `artifact_generation`. Pass it as
  `expected_artifact_generation` when requesting another offset.
- Record summaries carry numeric `level` and a `level_basis` for actor level,
  item level, or spell rank. For annotated section HTML, request
  `include_section_rendering: true`.
- Multi-field reads return the selected fields for replay. Retained reads
  report a generation conflict before looking up the selection. CLI graph links
  and occurrences return navigation you can pass to `record get --navigation`.
  Browser table rolls return the matched reading content and navigation. CLI
  table rolls retain detailed results for those matches.
- `POST /api/related` reports availability by link direction and includes
  additional outgoing links. Open the matching Search direction for paged
  results. The former seed and remaster detail objects have been removed.

**Saved lists, characters, parties, and encounters**

- `lists create --json` returns `data.list_key` and `data.slug`. Creating an empty
  list returns the batch receipt with zero counts and an empty item array.
  Fetch the list by key for its metadata. Deleting a list or encounter requires
  its stable key in both CLI and HTTP. Retain that key for retries.
- `characters preview --json` returns compact facts. For example, a coin amount
  previously returned as `{"state":"value","value":50}` now appears as `50`.
  Use `--detail full` for tagged facts. Both formats include the guards needed to
  save the import. To retry a Pathbuilder refresh after a lost response, reuse
  the same `characters refresh --request-id` and reviewed inputs.
- Renaming a character preserves its level. In a character PATCH, omit the
  level to keep it, send null to clear it, or send an integer to set it.
  In a party PATCH, omit `level_updates` to preserve all levels. Each supplied
  entry must specify a number or null.
- `parties list --json` and the HTTP party directory return summaries with member
  counts. Use `--detail full` for all rosters in the CLI. In HTTP, fetch one
  party by key or use `GET /api/parties/rosters` for all rosters.
- When adding a record to an encounter, `POST /api/encounters/{encounter_ref}/participants/record`
  accepts quantities from 1 through 50. In the query parameters,
  reuse the `expected_revision` sent in the preview
  request and pass the returned `addition_generation` as `expected_artifact_generation`.
  If the encounter changes, review a fresh difficulty preview before adding.
  Use `GET /api/encounters/{encounter_ref}/settings` for saved encounter metadata.
- Condition PATCH preserves omitted fields and defaults to a correction. Supply
  explicit application intent to apply gameplay effects.

**Validation and installation**

- `index check` defaults to a shallow check in text and JSON. Use `--detail full`
  for the previous JSON statistics. Both `index check` and `index validate`
  return `data.valid`. An invalid artifact exits 3 with `data.valid: false` and
  `data.reason`. A check that cannot run exits 3 with a top-level error.
- `index build` exits 2 for invalid configuration and 3 for an unusable workspace
  or failed build. Invalid path and query parameters on documented HTTP routes
  return a JSON application error.
- `agent skills install --json` requires a target, scope and confirmation.
  Installation failures exit 3. The skill doctor identifies a file blocking
  the installation directory.

## Known issues

The macOS desktop app is ad-hoc signed and unnotarized. The Windows installer
is unsigned. If your operating system shows a first-launch warning, follow the
platform-specific steps in the [installation guide](https://github.com/e-kosten/pf2e-atlas/blob/release/v0.1.0/docs/installation.md).
