# v0.1.0

## Summary

Search and record commands fetch the detail you request. Character edits preserve saved levels, and a Pathbuilder re-import can recover its acknowledgment after a disconnect.

## Install Notes

Atlas aims to preserve your saved work through upgrades. During 0.x, commands,
defaults and response shapes may evolve. Automations can target an installed
version and use these notes when moving to the next release.

See [setup and maintenance](../setup-and-maintenance.md) for installation and workspace upgrade steps.

## CLI and API changes

- Renaming a character preserves its level. In a character PATCH, omit the level
  to keep it, send null to clear it, or send an integer to set it.
- Pathbuilder re-import can recover a committed update after a lost response.
  For a retry across CLI invocations supply the same `characters refresh
  --request-id` and reviewed inputs on both attempts.
- `lists create --json` always returns `data.list_key` and `data.slug`. The
  empty-list invocation now returns the batch receipt with zero counts and an
  empty item array. Read the created list by key for its saved metadata.
- Ordinary CLI Search and Similar return compact evidence. Use `search --detail
  full` or `similar --explain` for all available evidence. HTTP search defaults
  to records only and reports the effective detail on each page.
- `index build` returns exit 2 for invalid configuration and exit 3 for an
  unusable workspace or a failed build. Invalid API path and query parameters
  on documented routes return a JSON application error.
- The HTTP party directory returns summaries with member counts. Fetch one
  party by key for its roster, or request `GET /api/parties/rosters` for the
  full directory. `parties list --json` still returns full rosters.
- Multi-field record reads include the selected fields for replay. Browser
  table rolls return the matched reading content and navigation. CLI table
  rolls retain detailed results for those same matches.
- In `POST /api/related`, reference categories now report incoming and outgoing
  availability and the additional outgoing links. Callers can open the matching
  Search direction for paged results. The response omits the former seed and
  remaster detail objects.
- When adding a record to an existing encounter, pass the same
  `expected_revision` used in the difficulty preview request. Pass the preview
  response’s `addition_generation` as `expected_artifact_generation`. Both are
  query parameters on the addition request. If the encounter changes, refresh
  the preview and review the new difficulty.
- Deleting a list or encounter now requires its stable key in HTTP and CLI.
  Look it up by slug once, then retain the key for deletion and retries.
  This protects a replacement that later takes the same slug.
- In a party PATCH, omit `level_updates` to preserve every level. Each supplied
  entry must explicitly set `level` to a number or null. Encounter record
  additions accept quantities from 1 through 50 in both preview and commit.
- `filters fields --json` now returns group summaries such as
  `{"id":"movement","label":"Movement"}`. Use `--detail full --json` for the
  previous grouped descriptors, or `--all --json` for the flat catalog.
- `characters preview --json` uses compact facts for proposed and current
  sections. For example, a supplied coin amount previously appeared as
  `{"state":"value","value":50}` and now appears as `50`. Use `--detail full`
  for tagged facts. Either format carries the guards needed to save the import.
- `index check` and `index validate` report `data.valid`. A completed check
  that finds an invalid artifact exits 3 with `data.valid: false` and
  `data.reason`. A check that cannot run exits 3 with a top-level error.
- Retained record reads report a generation conflict before looking up the
  selection. CLI graph links and occurrences carry replayable navigation at
  standard and full detail. Use the returned locator with `record get --navigation`.
- HTTP readers that need annotated section HTML for selection can request
  `include_section_rendering: true`. Ordinary reading returns the display content.
  Use `GET /api/encounters/{encounter_ref}/settings` for saved encounter metadata.
