# Effect Reference Presentation

Status: done
Priority: soon
Owner: unassigned
Last reviewed: 2026-10-18

## Outcome

Present effect references compactly using exact source facts. Preserve every
destination and explicit label. This is a separate workstream from shared
presentation polish; it does not classify references as redundant or applied.

## Research

Inspect representative spell, item and ability references, including exceptions.
Schadenfreude and Heroism largely repeat their effects' descriptions; Bless
links an aura to an applied effect; Runic Weapon adds weapon selection; Mirror
Image uses a counter without rule elements. Enlarge Companion's effect expands
mechanics that its spell incorporates through a reference to Enlarge.

The research found no universal source field identifying a reference's semantic
role. Neither effect type, name prefix, rule presence nor similar prose proves
redundancy. The agreed presentation uses the exact resolved item family and
explicit-label presence. A single unlabeled effect destination in a parsed block
uses an icon and “Effect”; multiple distinct destinations retain names. Explicit
labels and HTML anchor contents stay unchanged. Full names remain accessible in
tooltips and previews. No links are removed, relocated or manually classified.

## Acceptance

- Verify the approved compact treatment in the working product.
- Document the decision and exceptions beside the owning implementation.
- Test explicit labels, distinct destinations, structural blocks, unresolved
  targets, native navigation and shared previews.
- Preserve underlying effect data for future encounter application, duration,
  counters and automation; this task does not implement that automation.
- Keep search text and graph destinations unchanged; validate prepared-cache
  refresh separately from embedding inference.
